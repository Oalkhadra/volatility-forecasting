5. COMPLETE TIMELINE EXAMPLE
   ═══════════════════════════════════════════════════════════════════════════
   
   Day 1-29:  Not enough data, returns None (strategy uses default 0.2)
   
   Day 30:    First vol estimate ready!
              returns = [r1, r2, ..., r29]
              vol = std(returns) * sqrt(252) = 0.18 (18%)
   
   Day 31:    New price comes in
              update(new=381, prev=380)
              returns = [r2, r3, ..., r30]  (dropped r1, added r30)
              vol = 0.19 (19%)
   
   Day 50:    Market volatility spikes
              Recent returns show big moves
              vol = 0.35 (35%)
              
   Day 60:    Volatility mean-reverts
              Old volatile returns drop out of window
              vol = 0.22 (22%)

   This "rolling" nature means historical vol adapts to changing market
   conditions, but always lags (uses past data only, no prediction).


KEY INSIGHT:
────────────
The historical model is the SIMPLEST possible approach:
  "Whatever volatility was in the past 30 days, use that for pricing options"

If this beats GARCH/ML, it tells you:
  1. Recent vol is highly predictive of near-term vol (vol persistence)
  2. More complex models might be overfitting
  3. Transaction costs favor simple approaches

If GARCH/ML beat historical, it tells you:
  1. There are patterns in vol dynamics beyond simple persistence
  2. Predictive modeling adds value
  3. Complexity is justified
